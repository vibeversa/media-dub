# Dubbing Platform

A media dubbing platform: upload a source video/audio, transcribe, translate,
assign voices, synthesize speech, mix, and render a dubbed output — with
traceability, review, quota, and operational safeguards at every stage.

The backend is a .NET 10 modular monolith (ASP.NET Core API + workload-specific
worker services); PostgreSQL is the system of record, Redis is ephemeral only,
and object storage holds immutable artifacts. Media work runs through FFmpeg;
AI capabilities are provider-abstracted with deterministic mocks as the
default. A React frontend ships in `frontend/`.

## Prerequisites

- .NET SDK 10.0.100+ (pinned in `global.json`) — the solution targets `net10.0`
  with nullable reference types, implicit usings, and warnings-as-errors.
- Docker (for `docker compose` and Testcontainers-backed integration tests).
- FFmpeg on `PATH` for media tests and media worker readiness.
- Node.js 24 + npm for the frontend and API client tooling.

## Build and test

```bash
dotnet tool restore
dotnet build
dotnet test
```

Convenience targets (see `Makefile`):

```bash
make build            # dotnet build
make test             # dotnet test (all projects)
make test-unit        # unit tests only
make test-integration # integration tests only
make test-e2e         # E2E smoke only
make migrate          # apply EF Core migrations to the default database
make lint             # build with code-style enforcement
make generate-api     # regenerate the frontend API client from openapi.v1.json
make check-api-drift  # fail if the committed generated client is stale
```

Integration and E2E tiers use Testcontainers (PostgreSQL 16, RabbitMQ 3.13,
Redis 7, MinIO) and skip cleanly when Docker is unavailable. Media fixtures are
generated by `scripts/generate-fixtures.sh` (requires FFmpeg); the E2E suite
references them but does not require the binaries, so it still passes on a
machine without generated fixtures.

## Local development

Fast and full local profiles share PostgreSQL 16 + MinIO; the fast profile runs
without RabbitMQ/Redis using the in-memory transport and mock providers.

```bash
# Fast (default local): postgres, minio, api, control
docker compose --profile fast up --build

# Full: adds rabbitmq, redis, and all workers
docker compose --profile full up --build
```

Ports are overridable via `POSTGRES_PORT`, `RABBITMQ_PORT`,
`RABBITMQ_MANAGEMENT_PORT`, `REDIS_PORT`, `MINIO_PORT`, `MINIO_CONSOLE_PORT`,
and `API_PORT` (defaults: 5432, 5672, 15672, 6379, 9000, 9001, 8080).

Health endpoints:

```bash
curl -f http://localhost:8080/health/live    # liveness, process-local only
curl -f http://localhost:8080/health/ready   # readiness, dependency-aware
curl -f http://localhost:8080/metrics        # Prometheus exposition (API only)
```

`/health/live` never checks dependencies, so an unhealthy dependency can never
restart a live process via liveness. `/health/ready` requires PostgreSQL and
storage always, adds RabbitMQ/Redis under the full profile, and adds FFmpeg,
provider, or GPU checks for the matching worker roles. See `LOCAL_PROFILES.md`
for the full profile and probe matrix.

## Pipeline

A run advances through fixed stages (`StageType`):

```
MediaValidation -> MediaAnalysis -> AudioPreparation -> SourceSeparation ->
Vad -> SegmentBuild -> Diarization -> Transcription -> ContextBuild ->
Translation -> VoiceAssignment -> VoiceGeneration -> TimingOptimization ->
TimelineAssembly -> AudioMixing -> QualityControl -> Render
```

Stages execute through a saga/DAG with per-stage leases and barriers; failure
and quality outcomes are distinct, and retries are dependency-aware. Source
separation and enrichment stages are optional and feature-flagged.

## Configuration

Configuration is layered through `appsettings.json` plus environment variables
(double-underscore syntax, e.g. `ConnectionStrings__Default`,
`Transport__Provider`, `Providers__DefaultProvider`). Local-only defaults live
in `docker-compose.yml`; production secrets come from an external secret
manager — never from git. Notable switches:

- `Transport__Provider` — `InMemory` (fast local default) or `RabbitMq`.
- `Providers__DefaultProvider` — `mock` by default; real adapters register as
  `azure`/`openai`/`google`/`gemini`/`local` (see
  `src/DubbingPlatform.Infrastructure/Providers/README.md`).
- `Features__LocalInferenceEnabled` — gates the optional local/GPU sidecar
  (`contracts/local-inference/README.md`), disabled by default.

## Frontend

```bash
npm --prefix frontend install
npm --prefix frontend run dev        # Vite dev server
npm --prefix frontend run build      # typecheck + production build
npm --prefix frontend run test       # vitest component tests
npm --prefix frontend run lint       # eslint (zero warnings)
```

The frontend consumes only the committed generated client under
`frontend/src/api/generated/`; the build's `prebuild` step fails on API drift.
See `docs/api-contract.md` for the source-of-truth chain and regeneration rules.

## Deployment

CI (`.github/workflows/ci.yml`) restores, builds with warnings-as-errors, runs
unit/integration/contract/E2E-smoke tests, builds and scans the container
images (Trivy), generates an SBOM, signs with cosign, and publishes to GHCR on
`main`. Cluster rollout uses the raw Kubernetes manifests in `deploy/k8s/`
(primary) or the thin Helm wrapper; `deploy/README.md` is the authoritative
deploy guide covering prerequisites, deploy order, rollback, launch gates, and
scaling. Validate manifests locally with `bash deploy/verify.sh`.

Production hardening covers HA topology, RPO 5 min / RTO 1 h, backup/restore,
chaos, load, and secret-rotation drills; promotion gates are documented in
`deploy/README.md`.
