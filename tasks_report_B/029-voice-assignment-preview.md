## Decisions Made
- **Bundle-plus-speakerId for previews (drift documented):** OpenAPI `VoicePreviewRequest{voiceId,text}` omits `speakerId`, but `SpeakersController.CreatePreview` requires `{speakerId,voiceId,text?}` for ownership checks. Frontend sends bundle fields plus `speakerId` as an additive JSON property (cast through `VoicePreviewRequest`, never a query param, never logged), mirroring Task 028 bundle-wins with additive compat.
- **`queryKeys.voices` as child of project detail:** `all=['projects','detail',id,'voices']`, `available=[...,'available',speakerId]`, `preview=[...,'preview',previewId]` so prefix invalidation from `project.detail` cascades; `useSpeakers` stays on `queryKeys.speakers.list` per spec, available-voices gets its own scope to avoid colliding with `speakers.detail`.
- **Consent defaults to valid:** compatible-list voices carry no explicit consent field in production (server already filtered); `consentStateFor` returns `valid` when no consent keys/flags present, and fixtures inject `consentStatus` + `tenantPolicyMessage` for `consent-required|revoked|unavailable` tests. Policy messages render verbatim, no client legal interpretation.
- **Reset as default-voice assignment:** no dedicated reset endpoint exists; reset assigns `defaultVoiceFor` (`isDefault` flag, else first compatible) behind the same `ImpactDialog` (`mode='reset'`). Disabled when unassigned or no compatible voices, with explanatory `title` tooltip.
- **Preview URL hygiene:** URL lives in `useState` only (no storage, no logs, no query params beyond the provided URL); `referrerpolicy=no-referrer` set imperatively via `audioRef` to keep JSX typed across React versions and respect `Referrer-Policy`.
- **Error path discipline:** assignment 403/409 clears pending, shows `voices-assign-banner` with backend message verbatim + `Ref:` correlation, then refetches; other failures stay in-banner; successes use `ToastProvider` only. No ad-hoc toasts for errors.
