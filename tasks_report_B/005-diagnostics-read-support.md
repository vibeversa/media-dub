## Decisions Made
- **No new public error codes (`ErrorCodes.All` stays 29):** the required `DIAGNOSTICS_FORBIDDEN` code is carried as a message marker on `ForbiddenException` (public code `FORBIDDEN`/403), same marker convention as Tasks 003/004. The catalog stays frozen until Task 013.
- **TenantAdmin equivalence at the data layer:** tenant-wide admin has no membership table (roles live in JWT claims), so the default checker grants viewership to active `TenantUser`s holding a `ProjectOwner` membership in the tenant — the strongest tenant-scoped elevation persisted in the DB. JWT `TenantAdmin`/`Operator` roles and the `diagnostics.view` permission are evaluated via pure `DiagnosticsAccessPolicy.IsElevatedViewer` and re-checked at endpoints in Task 013 (defense in depth, documented on the checker).
- **No worker heartbeat table exists** (verified: zero heartbeat/heartbeat-table references in `src`): `WorkerHealthService` derives health from `StageExecution` lease state grouped by `LeaseOwner` (`UpdatedAt` = last-heartbeat proxy, same justification as stale leases), with `Diagnostics:KnownWorkers` roster entries surfacing `Unknown`/null-heartbeat. `Version` reads null — no runtime source exists; Task 038 owns version reporting.
- **Queue depths are bus-level, entity reads are tenant-scoped:** the MassTransit outbox carries no tenant, so depths/DLQ are bus aggregates behind the same elevated guard; all `StageExecution`/`ContentObject`/`ReviewItem`/`ProviderExecution` reads run inside `TenantContext.BeginScope(tenantId)` with query filters + explicit tenant predicates.
- **Orphan cursor is an opaque skip count** (not keyset): `Guid` comparisons are not safely translatable on the Npgsql provider, while `Skip/Take` over the stable `(CreatedAt, Id)` ordering is; unparsable cursors restart at zero. Deep-table scans remain the retention workers' job (documented).
- **InMemory EF added to UnitTests (test-only):** the only way to prove R5 hermetically (zero `ChangeTracker` entries after all eight query paths) without Docker/PostgreSQL. Production code is untouched by this; `TenantModelCacheKeyFactory` is wired in tests so tenant filters never leak across contexts.
