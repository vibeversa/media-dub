## Decisions Made
- **Activity nests under project detail:** `queryKeys.activity.all(projectId)=['projects','detail',projectId,'activity']` so prefix invalidation cascades and `keysForEvent` can scope to the open project only (empty when `projectId` absent, never whole-cache). `list(projectId,{page,pageSize})` carries paging; `lists(projectId)` is the list prefix.
- **Preferences factory mirrors notifications key:** `queryKeys.preferences.all=['me','preferences']`, `detail(key)=['me','preferences',key]` matches `prefsQueryKey()=['me','preferences','notificationPreferences']` from Task 034, so the center toggles and settings screen share the same prefix without duplication.
- **Cost gets its own scope:** `queryKeys.cost.detail(projectId)=['projects','detail',projectId,'cost']` instead of reusing `workspace.detail` (which would collide caches with `useWorkspace`). Registry includes `cost.detail` wherever `workspace.detail` invalidates; `stage.progress` invalidates activity only (no cost impact).
- **Backend activity is thin:** `WorkspaceController.GetActivity` returns only `id/summary/occurredAt`; actor/action/advanced parse defensively with `System`/`Updated` fallbacks and email→`Team member` sanitization. Advanced allowlist is `run/runId/stage/phase/status/attempt/correlation/provider/cost` only; everything matching reservation/secret/token/url/lease fragments is dropped before render.
- **Filters are client-side:** backend has no filter params (unknown query ignored), so `filterActivityEvents` narrows the fetched page in memory (mirroring project-list client refinements). URL holds `actor/action/from/to` + `page`; `setFilters` strips `page`, `resetFilters` strips all five.
- **Estimate is a client mirror:** no dedicated estimate endpoint exists, so `useCostQuota` guesses segments via `ceil(durationMs/5000)` (server `PreflightAsync` branch, 10 fallback, 2000 clamp) and `estimateRunCostUsd`, always rendered with `Estimate` label + never-a-promise note. Actuals are `workspace.runCost` + `dashboard.monthToDate`; missing all three yields `costUnavailable` → `UnavailableState`, never zero-fill.
- **Reserved never fabricates ids:** `reservedUsd` stays `undefined` (backend exposes no separate hold field); `deriveQuotaState` still maps `reserved` when a positive hold arrives (unit + banner cover it), and `CostSummary` renders reserved totals as informational only with no id field anywhere.
- **Settings stores strings:** `locale/timezone/theme` PUT plain strings, `defaultProjectFilters/timelineZoom/notificationPreferences` PUT JSON-stringified values (matching the notifications `notificationPreferences` pattern). Timezone blur-saves (not keystroke) to avoid 400 storms; theme `setTheme` fires before PUT for instant apply.
