## Decisions Made
- **No MSW, direct fetch mocks:** the task suggests MSW, but a new `msw` runtime closure would churn the pinned toolchain (Task 014 pins) for zero extra assertion power. `setInnerFetchForTests` swaps the interceptor's inner fetch so tests observe exact headers, retry counts, and key reuse hermetically. Documented deviation; completion criteria (api tests pass) hold.
- **`apiClient` throws pre-flight, `anonymousClient` doesn't:** the spec's "default throws `NOT_AUTHENTICATED`" is implemented literally via `requireAccessToken` as the generated client's `getToken`, so unauthenticated calls reject before touching the network. Login/refresh (which mint secrets and never take idempotency keys per the bundle) use `anonymousClient`; Task 019 registers the provider post-login and clears it on logout. `apiFetch` takes `auth?: boolean` (default true) for the same split.
- **Correlation via scoped global interceptor:** the generated client calls `globalThis.fetch` directly and its `RequestOptions` has no correlation slot, so header injection without touching generated code requires patching fetch. The patch is scoped to `/api/v1` URLs only (everything else passes through untouched), injects the ID, retries GETs, and emits `auth:expired`. `apiFetch` shares the same `coreFetch`, so both paths behave identically. `getLastCorrelationId()` is a documented fallback; per-request IDs on normalized errors are the primary telemetry handoff for Task 018.
- **Kind mapping judgment calls (no `NotFound` kind exists):** 404-family codes (`NOT_FOUND`, `PROJECT_NOT_FOUND`, `VERSION_NOT_FOUND`, `VOICE_NOT_FOUND`) map to `Validation` ("may have been deleted or lack access"); `ARTIFACT_UNAVAILABLE` maps to `Media`; review-domain 409s (`SELECTION_CONFLICT`, `REVIEW_VERSION_CONFLICT`, `REVIEW_ALREADY_RESOLVED/NOT_RESOLVED`, `MANUAL_REVIEW_REQUIRED`) map to `Review`; `DUPLICATE_MEDIA`/`SEGMENT_RETRY_ACTIVE`/`EXPORT_*`/`OUTPUT_INCOMPLETE` map to `Conflict`. Counts verify to exactly 65 (16/10/14/7/6/5/7).
- **`retryable` semantics:** true only for GET + (network failure or 502/503/504), plus any-method network failure as an explicit-retry hint (transport still never auto-retries mutations). 401/429/validation never retryable. Abort is `Unknown` + non-retryable.
- **`useAppMutation` key lifecycle:** caller key wins and never rotates; otherwise one key per attempt, rotated on settle — rapid double-submits share a key (one effective request server-side) while later distinct submits differ. Thrown errors are normalized with `{ method: 'POST' }`.
- **R1 scan semantics:** bans `queryKey:` followed by an inline literal (`[`, `'`, `"`, backtick) outside `api/queryKeys` (tests excluded). Factory references like `queryKey: queryKeys.project(id)` remain legal — a literal ban on the property name itself would outlaw every `useQuery` call.
- **`NOT_AUTHENTICATED`/`NETWORK_ERROR` live in `kinds.ts`** (single owner) to avoid `export *` collisions between the client and errors barrels; `httpClient` re-exports the former for transport callers.
