## Decisions Made
- **Conventional `/admin/*` reads for tenants/users/audit/retention/flags with 404→EmptyState degradation:** the generated bundle (Task 014) has no such endpoints, so these hooks call `apiFetch` on conventional paths and treat 404-unknown-marker as "not provisioned" rather than failure. Real reads (usage/quotas/health/routes/diagnostics) use the generated client. Documented as frontend-anticipated contracts pending backend provisioning.
- **Permission-string grant ranks:** the store keeps permission strings, not role claims, so `ADMIN_ROLE_RANKS` maps `admin.manage`/`admin:read`→5 and `diagnostics.view`→2 alongside role names; `canAssignRole` stays strictly-higher. Server re-authorizes everything; this is a UX pre-check only.
- **Narrowed secret-key fragments (bug found by E2E):** the first `@admin` run showed "Queues idle" because `media.prepare` contains the `media` fragment and was dropped as "secret". Removed domain words (`media/audio/video/payload/body`) from `isForbiddenAdminKey`; true secret fragments retained. The leak scan (`findSecretLeak`) keeps its broader value list for R5.
- **No backend destructive endpoints created:** the admin surface is read-only; `AdminAuthzTests` asserts destructive-shaped POST/PUT/DELETE return 404 + marker (never execute). Destructive flows are frontend-gated with audit bodies ready for future endpoints.
- **`useDiagnosticsPoll`/`useOptionalAdminList` hook-helper naming:** plain helpers calling hooks violate `react-hooks/rules-of-hooks`; renamed with `use` prefix to satisfy lint.
- **R1-scan-safe comments:** `` `queryKey:` `` with closing backtick trips the `queryKey\s*:\s*['"`[]` repo scan even in comments; reworded to "ad-hoc key literals".
