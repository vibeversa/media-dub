# 006 — Auth, Session, Me, Preferences API

## Status
COMPLETED

## Summary
Exposed `POST /api/v1/auth/login|refresh|logout`, `GET /api/v1/me`, and `GET|PUT /api/v1/me/preferences` with the 12-permission UX-hint contract (`Permissions.All`, set-equality tested). New `AuthService` issues short-lived HS256 access JWTs plus opaque refresh tokens persisted as salted SHA-256 hashes in a new `refresh_sessions` table (RLS + migration); refresh rotates within the same family and reuse revokes the whole family (401 `TOKEN_REUSED`). Added 7 catalogued error codes (`INVALID_CREDENTIALS`, `TOKEN_EXPIRED`, `TOKEN_REUSED`, `USER_DISABLED`, `PREFERENCE_KEY_UNKNOWN`, `PREFERENCE_VALUE_TOO_LARGE`, `TENANT_REQUIRED`; catalog 29→36), ASP.NET Core rate limiting (login 5/min/IP, refresh 30/min/user, `AuthRateLimit:Enabled` relaxation), OpenAPI annotations with auth/me idempotency exemption, and audit on login/logout. `MePreferencesTests` (12 integration tests, Docker-gated) plus hermetic `AuthSessionTests` (7 unit tests) verify round-trip, TTL-irrelevant rotation, family revocation, idempotent logout, isolation, and 429 burst.

## Decisions Made
- **Catalog grows 29→36 (overrides the 005 "frozen until 013" note):** Task 006 explicitly mandates new envelope codes (`TOKEN_REUSED`, `INVALID_CREDENTIALS`, `TOKEN_EXPIRED`, `USER_DISABLED`, `PREFERENCE_KEY_UNKNOWN`, `TENANT_REQUIRED`, plus a 413 code). Marker-in-message (Tasks 003–005 convention) cannot satisfy "401 `TOKEN_REUSED`" envelope assertions, so the codes join `ErrorCodes.All` with `StatusFor` mappings; the two count-pinned tests were updated to the new intentional sizes rather than deleted.
- **413 code is `PREFERENCE_VALUE_TOO_LARGE`:** the task names a 413 status but no code; a distinct code beats overloading `VALIDATION_FAILED` (whose catalog status is 400) and keeps the oversize path greppable. 429 reuses the existing `RATE_LIMITED` via the framework limiter (plain 429, no envelope — status-only assertion).
- **Durable refresh sessions (new table) over in-memory store:** reuse detection + family revocation require server state that survives restarts and works across instances; opaque `{id}.{secret}` wire format gives O(1) lookup with per-session salt. Unknown/unparsable refresh → `TOKEN_EXPIRED` (login redirect, no enumeration); revoked reuse → `TOKEN_REUSED` + whole-family revoke; logout revokes one session, idempotent 200.
- **External-subject login (no passwords):** "external credential" = `(tenantId, externalSubject)` pair matching `TenantUser`; unknown pair → `INVALID_CREDENTIALS` (no enumeration), known-disabled → `USER_DISABLED`. JWT `sub` carries the user Guid so `/me` resolves without lookup ambiguity; legacy `sub=test-user` style tokens get 401 `INVALID_CREDENTIALS` on `/me`.
- **`/me` tenant handling:** uses `TryGetTenantId` → 401 `TENANT_REQUIRED` instead of the shared `GetTenantId()` 403, per the task's edge-case table; no `?tenantId` override is read anywhere.
- **Permission mapping:** mirrors `RoleMatrix` exactly; `diagnostics.view` follows the Task 005 ProjectOwner≈tenant-admin elevation (Owner gets it, Editor and below do not); `admin.manage` is TenantAdmin/Service-only so no membership role grants it; `Operator` JWT adds `diagnostics.view` only.
- **Refresh rate-limit key:** the limiter runs before authentication/body parsing, so the refresh policy partitions by JWT `sub` when present else remote IP (anonymous refresh has no JWT); documented on the policy. CI relaxation is `AuthRateLimit:Enabled=false` (NoLimiter), used by all integration tests except the burst test.
