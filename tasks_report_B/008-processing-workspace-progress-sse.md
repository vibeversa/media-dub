## Decisions Made
- **Explicit processing idempotency vs generic filter:** `POST processing` and `POST processing/{runId}/retry` use `ProcessingIdempotency` (`Endpoint="processing"`, 24h, shared start/retry namespace) not `IdempotencyFilter` (per-`METHOD path`, 7d) so retry reuse of a start key yields 422 `IDEMPOTENCY_KEY_REUSED` and replay yields 200+`Idempotent-Replayed:true`. Legacy `POST processing/cancel|retry` (selective) keep the generic filter (24h via `IdempotencyRetention`) for compat; `IdempotencyRetention.ProcessingStart=7d` left untouched for non-processing routes.
- **`GET processing` redefined to list:** task requires run-list paginated; existing single-active moved to `GET processing/active` (literal beats `{runId}` param). No HTTP tests covered the old shape; `GET processing/{runId}` unchanged.
- **Per-run cancel/retry added, legacy kept:** `POST processing/{runId}/cancel` (terminal→`RUN_ALREADY_TERMINAL`, service `Conflict→RUN_ALREADY_TERMINAL` mapping applied to legacy cancel too) and `POST processing/{runId}/retry` (Failed-only new run, `retryOfRunId` in response+audit, no DB column — durable link is audit+response) coexist with legacy active-cancel and selective stage-retry.
- **Force semantics:** `?force=true` with `processing.retry` roles (`TenantAdmin|ProjectOwner|ProjectEditor|Service` via `User.HasAnyRole`, matching `RoleMatrix` retry entry) bypasses the app-level active check and creates a second active run (no partial-unique in snapshot, so DB allows it); without permission still 409 `RUN_ALREADY_ACTIVE`.
- **Progress superset not minimal:** `ProgressResponse` keeps all old fields plus `PercentApproximate` alias (=`PercentageIndicator`) to preserve compat while meeting R4; `notEta:true` always; bare runs (no summaries) return 0/null via `DeriveCurrentStage([])→null`.
- **Stream 404 vs 403:** project reads stay 403 cross-tenant per Task 007, but `GET progress/stream` does a tenant-scoped existence check (`RequireProjectStreamAsync`) →404 to avoid leaking via infinite transport; `prj_` ids bypass `ProjectOwnershipHandler` (raw-GUID-only) so controller decides. `Last-Event-ID` read and ignored (replay in Task 013); `?access_token=` handled in `Program.cs` only for `/stream`.
- **Workspace 12 keys vs “ten sections”:** spec lists 12 keys (`project,media,run,phase,stage,progress,review,warnings,output,cost,activity,permissions`); implemented exactly those, test asserts all 12 plus `X-Workspace-Queries≤12` (10 actual). Costs are display sums from `CostReservations` (Reserved/Actual); permissions from JWT roles only (no DB, `sub` is random GUID in tests so `PermissionResolver` DB path unusable).
- **SSE token safety:** query token set as `context.Token` only, never logged/audited; audits carry `correlationId`+`idempotencyKey`+`detail` (JSON quoting avoids `SecretRedactor` stripping `idempotencyKey`).
