## Decisions Made
- **Version = decision count, no migration:** `ReviewItem` has no version column, so `version` is the count of `ReviewDecision` rows (0 untouched, +1 per mutation). Uniform across legacy and hardened paths; stale writers get 409 with `{currentVersion}`. History is decisions oldest-first capped at 50 with envelope `truncated`.
- **Per-review idempotency namespace, not the generic filter:** new mutations skip `IdempotencyFilter` (per-`METHOD path`, no replay header) and claim `(tenant, review-mutation:{id:N}, key)` for 24h via `IdempotencyService`, returning `Idempotent-Replayed:true` on replay with zero new rows. Same key + different body → generic 409 `CONFLICT` (no new code; task silent on reuse).
- **Reopen bypasses `ReviewStateMachine` explicitly:** the machine pins terminal states as sinks and `StateMachineTests` forbids terminal→Open, so it stays frozen; `ReopenAsync` uses a conditional `UPDATE ... WHERE status<>'Open'` + `Requeue`-typed decision with `{action:Reopen}` metadata, audited. Reopen touches no run state (render open-review gate blocks completion while open); resolve/dismiss/edit reuse `ReviewService` resume semantics.
- **Decision-type reuse, no enum change:** resolve→Approve, dismiss→Reject, reopen→Requeue, edit→ResolveWithEdit (API action preserved in metadata + audit `review.resolve|dismiss|reopen|resolvewithedit`). No `ReviewDecisionType` or `ReviewStateMachine` changes, no migration.
- **Legacy `POST resolve` upgraded:** it occupied the `/resolve` route as a resolve-with-edit alias with no HTTP test coverage; it is now the hardened plain-resolve (Open→Approved). Approve/reject/requeue stay as Plan A aliases. Clients sending `{editedText}` must use `/resolve-with-edit`.
- **Context data mapping:** item type = `ScopeType`, severity = worst QC severity else `BLOCKED`-reason→high else medium; voice consent = `not_applicable|not_required|granted|required`; sync offset = `Actual-Target`, drift = non-`SyncAcceptable`; audio IDs only (`signedUrl` null, Task 012 owns URLs); `allowed` = state ∩ `review.resolve` from JWT roles (server re-authorizes; forged viewer resolve →403 via policy).
- **Reason truncation vs rejection:** over-500 reasons truncate post-strip (Task 003/009 convention); only blank reasons reject with `REVIEW_REASON_REQUIRED`. Edit text empty-after-strip → `REVIEW_EDIT_EMPTY`; overlong edit defers to `ReviewService` (400 `VALIDATION_FAILED`).
