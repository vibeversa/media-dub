## Summary
Added the `SegmentSelection` entity (explicit per-segment selection pointers plus a `SelectionVersion` optimistic-concurrency counter starting at 0, unique on `(TenantId, SegmentId)`) with its EF configuration, the `AddSegmentSelection` migration (table + indexes + embedded RLS), and RLS source entry. Added `SegmentSelectionService` with `SelectTranscriptAsync`/`SelectTranslationAsync`/`CreateManualTranscriptVersionAsync`/`CreateManualTranslationVersionAsync` — all requiring `expectedSelectionVersion`, bumping atomically via conditional `UPDATE ... WHERE SelectionVersion=@expected` (exactly one winner; stale writers get 409 `SegmentSelectionConflictException` and never overwrite), recording actor + sanitized reason + timestamp in `AuditEvent`, publishing the new `SegmentSelectionChanged` contract message for voice/timing invalidation, and returning `OutputStale`/`OUTPUT_STALE` when final output already exists. `SelectionConcurrencyTests` (12 tests) covers happy-path selects, stale-write 409 with unchanged state, concurrent race serialization, immutable manual-version creation, 404/400 version errors, cross-tenant/membership blocking, and post-output stale warnings.
No new public error codes were added (`ErrorCodes.All` stays 29); conflict/not-found/mismatch reuse `CONFLICT`/`NOT_FOUND`/`VALIDATION_FAILED` with `SELECTION_CONFLICT`/`VERSION_NOT_FOUND`/`VERSION_SEGMENT_MISMATCH` sub-code markers in the messages.

## Decisions Made
- **No new public error codes (stays 29):** `ErrorCodes.All` is frozen until Task 013 and `ErrorEnvelopeTests.All_29_Error_Codes_Are_Mappable` pins it. Stale writes throw `SegmentSelectionConflictException : AppException` with `ErrorCode = CONFLICT` (409) and `SELECTION_CONFLICT` in the message plus `CurrentSelectionVersion`/`CurrentTranscriptVersionId`/`CurrentTranslationVersionId` payload for the Task 009 refresh shape; missing versions throw `NotFoundException` with `VERSION_NOT_FOUND` in the message; cross-segment versions throw `DomainException` (400 `VALIDATION_FAILED`) with `VERSION_SEGMENT_MISMATCH`. (Also: `ConflictException` is `sealed`, so the conflict subclass derives from `AppException` directly.)
- **No pre-existing invalidation bus message existed:** the 17 contracts contain no voice/timing invalidation message, so "publish existing invalidation message" is interpreted as publishing via the existing MassTransit+outbox pipeline using the frozen `IntegrationMessage` envelope. The task-mandated `SegmentSelectionChanged` domain event IS the new (18th) durable contract; `MessageContractTests` count updated. Service publishes via `ISegmentSelectionEventPublisher` after commit (exceptions propagate; no swallow), keeping Application free of MassTransit.
- **No pre-existing output-stale flag existed:** `OutputAsset` has no stale column, so "existing output-state flag" is interpreted as `OutputAsset` row existence for the run. The service derives `OutputStale` from that existence check, returns `WarningCode = "OUTPUT_STALE"` (a result warning, NOT an `ErrorCodes` entry), and records staleness in the audit `DetailsJson`. No recompute, no new column.
- **Manual-version markers reused:** new manual rows use `ReviewService.ManualProvider = "manual"` / `ManualModel = "manual-review-v1"` (same convention as resolve-with-edit; no new provider vocabulary). Selects flip `IsSelected` via raw SQL like `ReviewService`; content columns are never updated in place.
- **Membership gate is membership-or-ownership:** mutations require `ProjectMembership` row or `DubbingProject.OwnerUserId == actor`; otherwise `ForbiddenException`. TenantAdmin/Service role elevation is endpoint-owned (Task 009); `GetAsync` is project-scoped read without an actor (viewer roles enforced by endpoints).
- **Reason sanitization truncates, manual text rejects:** `SanitizeReason` strips `<...>` tags, trims, truncates to 500 (never throws on length); `RequireManualText` trims and rejects empty / >5000 (mirrors `ReviewService.RequireEditedText` limit).
- **Creation race → conflict, not silent win:** simultaneous first-selects collide on the unique `(TenantId, SegmentId)` index; the loser’s `CONFLICT` save is translated to `SegmentSelectionConflictException` with re-read current values (exactly one winner either way).
