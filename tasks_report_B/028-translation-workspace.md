## Summary
Implemented the side-by-side translation review workspace on `queryKeys.translations` with a `TranslationWorkspace` (segment list + source/selected/alternatives panes + header strip) and a controlled `TranslationEditor` (glossary-highlighted draft, read-only duration/sync indicator, reading-speed hint). Select (`selectTranslationVersion`) and manual (`editTranslation`) POSTs send `expectedVersion` with 409 stale-banner + refetch + preserved draft, and `useDirtyGuard` gates every segment/route/tab leave with save/discard/cancel. Added `TranslationPage` at `/projects/:id/translation`, extended the SSE registry to invalidate translations, and landed 17 vitest tests plus 4 hermetic `@translation` Playwright tests.
Files Created/Modified: 14 files (10 created, 4 modified, 1 report).

## Decisions Made
- **Bundle shapes win (drift documented):** backend `SelectVersionRequest{versionId,expectedSelectionVersion}` vs OpenAPI `SegmentSelectionRequest{expectedVersion,selectedVersionIds}` — frontend follows bundle via `apiClient.selectTranslationVersion({expectedVersion,selectedVersionIds:[id]})` and `editTranslation({expectedVersion,text})`, mirroring Task 027 transcript (no generated-code edits, no backend scope).
- **`queryKeys.translations` as first-class scope:** `all=['projects','detail',id,'translations']`, `list=[...,'list']`, `detail=[...,'detail',seg]` so prefix invalidation cascades from `project.detail`; registry extended only for workspace-invalidating events, `stage.progress` intentionally omitted (too chatty, progress-only).
- **Single logical query, draft lifted to workspace:** `useTranslations` pages `listSegments(pageSize=200,max 10)` then hydrates `getSegment` detail only for rows with zero candidates; `draft:string` lives in `TranslationWorkspace` (not `TranslationEditor`) so `useDirtyGuard` can gate segment changes + `translation-back-link` route leave with one dialog; `TranslationEditor` stays controlled/presentational and independently testable.
- **409 never overwrites, save returns stay/go:** `isTranslationConflict({code,status})` branches on `SELECTION_CONFLICT`/409; select-409 shows banner+refetch (draft untouched), manual-409 shows banner+refetch+`setDraft(previousDraft)` (never auto-resubmit); `handleManualSave()->Promise<boolean>` returns `false` on 409/validation so `confirmSave` stays (no navigation), `true` on success so pending navigation follows.
- **Source-change rebase:** `baselineSourceRef` captures `sourceVersionId` when draft starts; a mid-edit `sourceVersionId` change while dirty raises `translation-source-changed` with `translation-rebase` (updates baseline, keeps draft) — covers transcript-version-moves-mid-edit without data loss.
- **Missing-data contract:** sync/glossary/voice absent renders `—` with explanatory `title` tooltip (never blank); glossary term with missing definition still `<mark>`s without `title` (no crash); provider/model shown only (no secrets); all texts React plain-text (no `dangerouslySetInnerHTML`, banned by eslint).
- **E2E stateful selection:** `mockTranslationApi` stores `world.selected[segmentId]=selectedVersionIds[0]` on select-POST and re-renders list/detail `isSelected` flags, so `translation-selected` visibly flips from `candidate B` to `candidate A` after select (otherwise refetch would return identical fixtures and the test could not assert a card update).
