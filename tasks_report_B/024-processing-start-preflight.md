## Decisions Made
- **Prompt conflict resolved as 024:** the header said 024-processing-start-preflight while `TARGET_TASK_FILE` still pointed at `023-resumable-upload-ux.md`; 023's report already exists as COMPLETED, so the stale pointer was treated as a copy-paste error and 024 executed (022 set this precedent).
- **No estimate endpoint in v1, so the estimate is a documented client mirror, not a fetch:** the bundle offers no per-run estimate operation (`ProcessingStartRequest` is `{configHash?}`; the server computes `EstimatePipeline` inside `PreflightAsync` at start). The dialog prices real speaker `segmentCount` sums through the server's own arithmetic and default price table, labeled "estimate" everywhere with a never-a-promise note; the server stays authoritative (429/409/403 mapped to panels). A backend estimate endpoint would replace the mirror one-for-one.
- **Quota honesty over task-literalism:** dashboard `quota.remaining` counts *projects created today* (`DashboardService`: `MaxProjectsPerDay − todayCount`), not runs — so remaining-after-run equals remaining, shown with that explanation, instead of a dishonest −1. The task's override-reason requirement is kept: exhausted daily quota forces an explicit reason before the costly start.
- **Warn, don't block, on media/archival status:** `ProcessingStartService` requires `MediaReady` exactly, but the dialog disables start only for load failure, conflict, unacknowledged consent, missing override, or in-flight (R5 covers conflicts). Unvalidated/archived states render warning panels and let the server 409 — the client can never wrongly block a future server relaxation.
- **Consent ack is captured, embodied, not shipped as a field:** v1 start has no consent/reason body fields, so the checkbox records user+timestamp (visible ack line) and the authenticated POST itself carries identity/time into the server's `processing.start` audit; voice consent is re-validated server-side at assignment (`VOICE_CONSENT_REQUIRED`).
- **Toast ownership by hosts, URL canonicalized by details:** the dialog reports `onStarted(runId)` only; hosts push `processing:toasts.started` and navigate to `?started=1`, which the details page strips silently — one toast, canonical URL, deterministic E2E via pre-click `waitForURL`.
- **No new query keys, no MSW:** preflight fetches imperatively on open (estimates must be fresh, never cached); terminal 202s invalidate existing factories. Tests use `setInnerFetchForTests` + `page.route` per repo convention, not MSW.
