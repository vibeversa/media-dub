## Summary
Added durable `Notification` and `ActivityEvent` entities with EF configurations, the `AddNotificationsActivity` migration (both tables, filtered unique dedup index, embedded RLS), and `ntf_`/`act_` public-ID prefixes. Added idempotent `NotificationProjector` (membership+owner recipient resolution, `SourceEventId` dedup, owner fallback then `notifications.skipped_total`, expiry-aware listing, mark-as-read) and append-only `ActivityProjector` (correlation+type+timestamp redelivery dedup, `(ProjectId, OccurredAt)` pagination, security-relevant actions also append `AuditEvent`), plus pure `NotificationEventMapper`/`ActivityEventMapper` from bus messages and a `NotificationActivityProjectionConsumer` subscribed to the existing published terminal events. All summaries/metadata carry short ids and codes only; sanitizers strip URLs/bearer tokens and `SecretRedactor` redacts secrets before the entity-level URL/token rejection. `NotificationActivityTests` (16 tests) verifies dedup, restart survival, pagination order, expiry exclusion with retention, cross-tenant isolation with live RLS, hostile-error-message exclusion, and audit co-write.

## Decisions Made
- **Enums over strings for Type/Severity/ActorType:** stored via `HasConversion<string>` like all existing enums, so DB values are readable and Task 012/013 wire names stay stable; unknown-future values fail closed at validation.
- **Null ProjectId rule enforced in the entity:** only `QuotaWarning`/`ProviderPolicyWarning` may be project-less; everything else throws. Tenant-wide quota/policy notifications resolve recipients to all `Active` `TenantUser`s (disabled users never notified).
- **Dedup keys:** notifications on `(TenantId, RecipientUserId, SourceEventId)` (filtered unique index + pre-check + CONFLICT-race re-read); activity has no natural unique key, so redelivery dedup is an exact-match check on `(TenantId, CorrelationId, Type, ProjectId, ProcessingRunId, OccurredAt)` — same message redelivered collides, distinct events differ in timestamp/correlation.
- **Sanitize-then-reject pipeline:** projectors strip bearer tokens entirely (`[redacted-token]`), redact `SecretRedactor` secrets, and replace URLs (`[redacted-url]`) so dirty input projects cleanly instead of poisoning; entities still reject raw URLs/`bearer ` as defense in depth. (Caught during validation: first version left `Bearer [REDACTED]`, which the entity would reject — fixed at the sanitizer, root cause, not the test.)
- **Run-failure bodies carry error code only:** `RunFailed.ErrorMessage` is never persisted (it may embed paths/secrets); verified by the hostile-message test.
- **`MediaValidated` valid → no notification:** only rejections notify; valid uploads are covered by the `MediaUploaded`→`UploadCompleted` activity. Export/quota/provider-policy have projector+mapper support but no bus messages exist yet, so they project via direct `ProjectAsync`/`AppendAsync` calls (bus wiring deferred to the task that introduces export-completion events; no new messages invented here).
- **Consumer placement:** new `NotificationActivityProjectionConsumer` in Infrastructure (Application must not reference MassTransit) subscribed to already-published events — outbox-delivered, at-least-once, idempotent via projector dedup. Fan-out across workload endpoints is harmless (first delivery wins, rest hit dedup reads) and terminal/review events are low-volume.
- **`ErrorCodes.All` untouched (stays 29):** no new public error codes; conflicts reuse the existing `CONFLICT` `DomainException` mapping.
