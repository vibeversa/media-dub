## Decisions Made
- **32-route map fixed explicitly (R1).** Task lists ~28 with ambiguous nesting (`.../processing`, `.../progress`, `/reviews/{id}` vs nested). Implemented 32: Projects 4 + Uploads 6 (incl. `GET uploads` list) + Processing 6 (`POST/GET processing`, `POST cancel/retry`, `GET progress`, `GET processing/{runId}`) + Segments 3 + Reviews 7 (nested list+single + top-level single + 4 actions) + Exports 4 + Output 1 + Admin 1. Verified via `Select-String Http(Get|Post|Delete)` count 32. No 501s remain (only comments mention 501).
- **Logical delete via `IsDeleted` shadow (no domain change, one migration).** `DubbingProject` stays dependency-free; EF shadow `IsDeleted bool DEFAULT false` avoids domain churn. `List/Get/Delete/RequireProject` filter via `EF.Property<bool>(p,"IsDeleted")`; `Delete` sets `Entry(...).Property("IsDeleted")=true`. Migration `AddProjectSoftDelete` also carries EF-regenerated outbox `bus_name` drop + 3 indexes (8.5.10 drift, transient safe, kept for snapshot consistency). Physical dereference deferred to 037 as tasked.
- **S3 multipart behind `IMultipartUploadClient` (Application stays AWS-free).** `Application` cannot reference `AWSSDK.S3` (only `Infrastructure` does); new abstraction keeps boundary. `S3MultipartUploadClient` uses `StorageOptions.Bucket` (never hardcoded), `ForcePathStyle`, presigned PUTs bound to `(key,uploadId,partNumber)` 15min. `UploadService` maps infra failures to 503 `STORAGE_UNAVAILABLE`; `ListParts` falls back to DB ledger when S3 unreachable so reads stay available; `Complete` requires `ceil(declared/8MB)` parts else 400 `UPLOAD_INCOMPLETE`. Publish (`MediaUploaded/RunStarted/ExportJobRequested`) lives in controllers via `IPublishEndpoint` best-effort try/catch (DB commit already succeeded, bus outage must not fail 200/202).
- **Public IDs `prj_/upl_` with dual-parse (no breaking 017 tests).** Responses expose prefixed strings (`ToPublic`); routes take `string` (no `:guid` constraint) and `PublicIdParser` accepts raw `D/N` + prefixed, wrong-prefix→400. Existing `IdempotencyTests` (which treat `id` opaquely and `GET {id}`) still pass hermetic 2/2; new tests assert `prj_/upl_` prefixes.
- **`ProjectService` owns hash/policy/audit (controllers thin).** Hash over `JsonObject{sourceLanguage,targetLanguage,settings:JsonNode.Parse(normalized)}` via `ConfigurationHashCalculator` (canonical, secrets stripped). `NormalizeSettings(null/whitespace→"{}"`, invalid JSON→400). Default `ProcessingPolicy(false,[],null,"default","default",false,null)` when tenant has none. `FluentValidation` validators per DTO exist for fail-fast 400s, but services re-validate for envelope consistency (`DomainException→400 VALIDATION_FAILED` via middleware, not `ProblemDetails`).
- **Thin pass-throughs return structured errors, never 501.** Processing start requires `MediaAssets Valid` else 409 (so 018 always 409 until 019 populates media); cancel/retry 404 when no run, 409 when illegal state; segments/reviews lists 200 empty, singles 404; exports `POST` 409 `EXPORT_NOT_READY` when no `Completed` run, download 409 until worker completes; output download 404 `ARTIFACT_UNAVAILABLE` until 033 renders. Real 15min URLs via `ArtifactService.GetDownloadUrlAsync(...,SignedUrlPolicy.DefaultExpiry)` when artifacts exist (no fake `https://downloads.local` placeholders).
- **Tests require PG+MinIO, skip without Docker.** Project-only tests need PG; upload flow needs PG+MinIO (real `PUT` to presigned URL, `Random(42)` 256KB, `video/mp4`, 1MB declared→1 expected part). Factory overrides `ConnectionStrings:Default`, `Storage:Endpoint/Bucket/UseSsl/AccessKey/SecretKey` (from `MinioContainer.Hostname/GetMappedPublicPort(9000)/GetAccessKey/GetSecretKey`), `Auth:SigningKey/Audience`, `Transport:Provider=InMemory`. Bucket `dubbing-test` ensured via `ListBuckets/PutBucket`. `SkippableFact` + Docker probe, `MigrateAsync`, `ConfigureAwait(true)`.
