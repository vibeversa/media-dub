## Decisions Made
- **No duplicate instruments for frozen names**: `quota.rejections`, `ratelimit.rejections`, `messaging.schema_mismatch_total`, `dlq.depth`, `storage.orphans_detected`, `cost.*`, `security.cross_tenant_rejected` already exist on other meters and are referenced as const aliases with forwarding intent; only genuinely new names got instruments on `dubbing-platform`. Duplicate same-name instruments across meters would double-export in Prometheus.
- **Application layer never references Infrastructure**: `ProviderExecutionRecorder` (Application) enriches traces via direct `Activity.SetTag` (identical tag names) instead of calling `TraceEnricher`; stage/review/cost wiring that would live in Application services is instead emitted from layer-safe callers (Api controllers, Infrastructure consumers/trackers, Workers). Documented in code comments.
- **`RequireTenantAdmin` = task's `RequireService|TenantAdmin`**: `AuthPolicies.AllowedRoles(RequireTenantAdmin)` is exactly `[TenantAdmin, Service]`; all diagnostics use this policy (Service satisfies every admin gate).
- **DLQ summary is DB-free; lists are DB-backed**: `dlq/summary` returns static queues/metrics/SLO guidance (always 200 for operators, useful during DB outages); `leases/status` and `reviews/backlog` query PG paginated (max 100). Audit `admin.access` still writes on every call, so the 200-admin path needs PG live.
- **403-viewer is live-only (repo precedent)**: hermetic JWT+authorized-403 was never verified repo-wide (all existing 403 tests are PG-backed `SkippableFact`s; hermetic coverage is 401-anon + policy-shape). `Diagnostics_Viewer_403` follows `Forbidden_Tenant_403` precedent: skips without Docker, live in CI. Same proven `new WebApplicationFactory + InMemory Auth keys + connectionString` shape as all passing live auth tests.
- **Lease tokens never exposed**: diagnostics return `LeaseOwner`/`LeaseExpiresAt`/`Status` but omit `LeaseToken`; review backlog omits `PayloadJson` (may carry edited text); provider detail exposes only hashes/ids/counts.
- **`Metrics_Scraped` starts the server before recording**: measurements published before any OTLP listener subscribes are lost; the test creates the client first, then records, then scrapes (root-caused the initial failure via a `/metrics` body dump showing only runtime/process scopes).
