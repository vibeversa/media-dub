## Decisions Made
- **Scope `Project` + queue `ai.provider` per code truth, not task text (`Run`/`media.render`)**: `StageGraph` scopes `QualityControl` as `(Project,single,[AudioMixing])` with `DispatchSingleWorkAsync` emitting `(Project,projectId D)` and `WorkQueueRouter.QueueFor(QualityControl)=AiProvider`; worker strictly requires `ScopeType.Project`. No `MassTransitConfig` change (extras already attach to `ai.provider`; `ShouldProcess` keeps sharing safe). Documented in worker docs (022/025/030/031 precedent).
- **`StageCompleted` is the render gate, `StageReviewRequired` blocks it**: no separate QC message contract exists; the saga dispatches `Render` only on QC `StageCompleted` per `StageGraph`, so review/retry/fail paths all block the render. Render itself stays Task 033.
- **Review rows created in the service, events in the worker**: task text says the worker creates reviews, but atomicity (results + report + review in tenant scope) and testability (no `ConsumeContext` needed) follow the Translation/TTS precedent — service returns `ReviewItemId`, worker publishes `StageReviewRequired`. Documented deviation.
- **Blocking rule default = review, not fail**: `BlockFailsRun=false` (default) routes `Blocked` to `MarkReviewRequired` + `StageReviewRequired` + `QC_BLOCKED` review (saga moves run to `ManualReviewRequired`, run awaits manual fix); `true` routes to `FailAsync(QC_BLOCKED)` + non-retryable `StageFailed` (saga fail-fast fails the run). `RetryRequired` (stale only) always takes the Translation-style retryable `StageFailed` path.
- **Checksum code uses the public catalog literal**: edge says `ARTIFACT_CHECKSUM_MISMATCH` while instructions suggest `QC_CHECKSUM_MISMATCH` — the public `ErrorCodes.ArtifactChecksumMismatch` wins (referenced as `CodeChecksumMismatch`), so checksum mismatches are queryable under the frozen code.
- **Stale metadata is run-attempt scoped**: `ProviderExecution` has no segment link, so freshness = any execution row with `Attempt == run.Attempt` (run-level, documented); per-segment stage-attempt nuance stays a provider-stage concern. Missing entirely also counts as stale → `RETRY_REQUIRED`.
- **Attenuation is a recorded-graph assertion, not a mix-RMS comparison**: the final mix is always louder inside dialogue (voice dominates), so inside<outside never holds there (031 root-caused); QC parses `volume={x}dB` from the `MixedAudio` metadata `filterComplex` and requires `|x − Mixing:DuckDb| ≤ 3` when a background stem exists (skipped dialogue-only). Signal-level duck is proven by mixer tests + `QcSignalTests`.
- **Silence-boundary gaps only apply dialogue-only**: background fills gaps by design, so gap-audibility warnings run only without background; overlap crossfade presence (audible window) warns per group (capped 20 windows/groups; unmeasurable probes skip, core gates stay fail-closed).
- **Application never references Infrastructure**: `FFmpegMixer.ParseTimeline`/profile statics are Infrastructure, so QC mirrors the tiny timeline/profile parsers (5–20 lines, documented mirrors of the schema-v1/mixer contracts) and consumes loudness targets via Domain `LoudnessTarget`; new signal capability went onto the Application-owned `IFFmpegService` abstraction instead.
- **`MIX_QUALITY`-style reasons**: `QC_BLOCKED`/`QC_REVIEW` are `ReviewItem` reasons (not `ErrorCodes` entries), matching 021/031 precedent; `StageGraph` `review-on-flag` already covers QC.
