## Decisions Made
- **Scope `Project` per `StageGraph`, not task-text `Run` (code truth)**: `StageGraph` scopes `AudioMixing` as `(Project,single,[TimelineAssembly])` with `DispatchSingleWorkAsync` emitting `(Project,projectId D)`; worker strictly requires `ScopeType.Project`. Documented in worker docs (030 precedent).
- **Queue `media.render` matches router, no `MassTransitConfig` change**: `WorkQueueRouter.QueueFor(AudioMixing)=MediaRender`; 030 already added the `MediaRender` `ConfigureConsumers` branch, now shared by `TimelineAssemblerWorker` + `AudioMixerWorker` via `ShouldProcess` (028 `ai.gpu` precedent).
- **`StageCompleted` is the task's "QC request"**: no QC message contract exists; saga dispatches `QualityControl` on `AudioMixing` completion per `StageGraph`. QC logic itself stays Task 032 (not implemented).
- **`MIX_QUALITY` is a review reason, not an `ErrorCodes` entry**: like 021 `SEPARATION_FALLBACK`, it lives as `FFmpegMixer.ReviewReason` on `ReviewItem` + `MarkReviewRequired` + `StageReviewRequired`; `StageGraph` says `no-review` for `AudioMixing` but 029 timing precedent shows review still applies (graph policy descriptive, not enforced).
- **Error mapping**: loudness-measure fail (after 1 internal retry) or out-of-tolerance → `PROVIDER_INVALID_RESPONSE` → worker review; persistent clipping (after one `alimiter=limit=0.95` + re-measure) or peak >-1 → `QC_BLOCKED` fail; disk/`TimeoutException`/`IOException` → `RESOURCE_EXHAUSTED` with output deleted and no artifact commit (wrapped as `ErrorCodeException` so `MessageDisposition` records permanent, not transient retry).
- **Layout always stereo 48kHz s16**: every input `aformat=fltp:48000:stereo` before placement; final `aformat=s16:48000:stereo`. Documented as deterministic superset (canonical preserves source, TTS mono 16k, background stereo 48k; stereo preserves all, loudness comparable). Task's `aformat=...:stereo?` resolved to always-stereo.
- **Critical `asplit` fix (root cause, not test deletion)**: initial premix reused `[dialog]` for both sidechain and `amix`; FFmpeg labels are single-use, so the second use got silence (inside dialogue mixed to near-silence). Fixed to `[dialog]asplit=2[dialogSC][dialogMix]`; verified via `astats` input-seeking (`-ss` before `-i`; output-seeking misleads on delayed audio).
- **Ducking verification on ducked background, not final mix**: final mix inside is always louder (dialogue dominates: e.g. -24dB inside vs -36dB outside), so `inside<outside` never holds there; `bgduck` alone with loud dialogue shows -50dB inside vs -36dB outside (-14dB duck). `Ducking_Applied` therefore verifies `VerifyDuckingAsync` on a sidechain-ducked background fixture (same `threshold=0.01:ratio=8:attack=150:release=150` + `volume=-12dB` params) plus asserts final `FilterComplex` contains `sidechaincompress` + `volume=-12dB` + `asplit` and `DuckingApplied=true`.
- **Stereo-aware RMS fix (root cause)**: `VerifyDuckingAsync` mapped ms→samples without dividing by channels (stereo `samples.Length` double-counted, windows misaligned). Fixed to frames (`samples.Length/channels`) with per-frame multi-channel accumulation; edge skip ±150ms so attack/release never decides; threshold `inside+0.5<outside`.
- **Profile precedence**: project `settings.loudnessProfile` (fail-closed `ParseLoudnessProfile`, `HasLoudnessProfile` gate) overrides `Mixing:Profile`; unknown profile → `VALIDATION_FAILED`; `TwoPass=false` falls back to single-pass dynamic loudnorm (default true = deterministic two-pass measure + `linear=true` apply with `measured_I/TP/LRA/thresh:offset` from first-pass JSON `input_*/target_offset`).
- **Stage metadata = artifact `metadata_json`**: `StageExecution` has no metadata column, so exact `-filter_complex` (`premix: ... || final: ...` plus `|| limiter:` when applied) plus levels Durations/profiles are stored in `MixedAudio` artifact `metadata_json` (canonical pattern via `UPDATE artifacts SET metadata_json`); parents are distinct `[timeline + dialogue audios + background?]`.
- **No new migration/config beyond `Mixing`**: reuses `artifacts`/`content_objects`/`artifact_parents`/`stage_output_artifacts`, `stage_executions`, `review_items`; worker owns `CompleteAsync` (Timeline pattern, not TTS service pattern) so no new Application service was added (task lists only mixer+worker).
