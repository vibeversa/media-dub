## Decisions Made
- **MassTransit 9.2.1→8.5.10 downgrade (biggest call).** Host boot smoke tests (new in 012) showed both Api and Workers crash at bus creation: `[Failure] License must be specified with SetLicense/... or MT_LICENSE/...` — v9 is commercial per https://masstransit.massient.com/configuration/license, and this project has no key (latent since 001 pinned 9.2.1; 011 never boot-tested hosts). Bisected with spike tests: minimal/test buses passed but real hosts failed; in-test host boot with identical config also passed, so the gate is process/entry-level, mechanism unclear — but docs are decisive, so investigation stopped there. 8.5.10 is Apache-2.0 (no gate), ships net10.0 targets, and every API used (outbox, saga, `ConfigureSaga/Consumer`, delayed scheduler, `context.Message`) resolved with zero code changes beyond versions. Post-downgrade: both hosts boot, bus starts (`loopback://localhost/`), outbox/inbox background services run against EF10/Npgsql10 (only errors are expected no-PostgreSQL-locally connection retries), `/health/live` 200, `/metrics` 200. Reports 001/006/011 keep their 9.2.1 notes as history; live code is 8.5.10 everywhere.
- **Spec `ConfigureDeadLetter(x=>x.SetQueueName("_error"))` does not exist** (verified in 8.5.10 and 9.2.1 package XML). DLQ is explicit application sends instead: poison/permanent→`_skipped`, missing-run/cross-tenant→`_error`, transient→rethrow into MT retry/fault pipeline; `DeadLetterQueueName=_error` frozen + `dlq.depth` metric; broker `*_error` queues remain for transport-exhausted faults (Task 38 alerts).
- **Saga terminal transitions via self-consumed outcome messages** (`RunCompleted/RunFailed/RunCancelled` published by handlers, consumed back for `TransitionTo`) — avoids exotic conditional-transition APIs; duplicates ignored in final states. `ManualReviewRequired` saga state is sticky-informational until a terminal outcome; the run *row* stays authoritative for projections (flips back to `Running` on resume).
- **Expired-lease takeover added to 011's claim path** (else worker-death recovery is theater: `RecoverStaleAsync` parks `RetryPending` but nobody could redrive — claimants failed fencing on dead owner/token). Takeover is fenced (`old owner+token+expired`), active leases never stolen, token rotation keeps dead workers fenced; 011 tests unaffected (all use active leases). Timeout consumer requeues recovered `RetryPending` units; saga re-pumps open barriers on each completion so bounded batches drain.
- **Review resumes and timeout requeues use fresh attempts** (not budget): operator/recovery-driven, clean leases; automatic stage retries consume `PerStageMaxAttempts`/`LogicalStageMaxAttempts`. `StageCompleted` with empty outputs on a skippable stage records `Skipped` (both count toward barriers, so misclassification is progression-safe).
- **Orchestration lives in Workers only** (`includeOrchestration`); Api publishes but hosts no saga/consumers (avoids split-brain with in-memory saga repo across competing consumers). Saga uses `InMemoryRepository`; durability story = PG rows (run/summaries/ledger) + outbox + idempotent replays; EF saga repo with migration is future work (documented limitation: process restart loses in-memory saga state; replay `RunStarted` to rebuild).
- Test scope: `BarrierTests` has 9 tests (6 required + scheduler-probe + takeover + saga E2E); PG parts `[SkippableFact]` (skip without Docker), bus parts plain Facts proven live on InMemory.
