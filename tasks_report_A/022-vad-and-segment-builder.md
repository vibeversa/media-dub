## Decisions Made
- **Queue/scope follow code truth, not task text**: task says Vad `ai.provider` + SegmentBuild `control.orchestration` with scope Run, but `WorkQueueRouter.QueueFor` maps both Vad and SegmentBuild → `media.preparation`, and `StageGraph` scopes both as `Project` (single). `MassTransitConfig` only attaches extra consumers to `media.preparation`. Both workers therefore share `media.preparation` with `ShouldProcess` pre-claim filters (like all prior media workers) and use `ScopeType.Project` claims via the saga/dispatcher. Documented in worker XML docs.
- **No separate VadService file**: task mandates `VadWorker` + `SegmentBuilderWorker/Service`; VAD orchestration (resolve/record/publish) lives inside `VadWorker` to avoid over-implementation, while segmentation pure logic lives in `SegmentBuilderService` for hermetic unit tests. `SegmentBuilderWorker` owns all DB commits.
- **Mock-only VAD gate fails permanently**: only `MockVadProvider` is registered (no keyed/azure/openai/google/local VAD adapters). Non-Mock resolver results throw `PROVIDER_CONFIGURATION_ERROR` (fail stage, no fallback — per task VAD has no fallback, unlike separation).
- **Single VAD call, no in-service retry**: transient I/O (`HttpRequestException/TimeoutException/SocketException/IOException` per `MessageDisposition.IsTransient`) rethrows via `StageWorkerFailure.TryFailAsync→false` into transport retry; permanent (`ErrorCodeException/DomainException`) fails + `StageFailed`. Matches task transient→retry/permanent→fail with zero extra retry code.
- **Segment quota checks both configs**: `Segment:MaxSegments` (new, 2000) AND `Quota:MaxSegmentCount` (existing, 2000); exceeding either throws `QUOTA_EXCEEDED` before any insert, and the worker's EF transaction guarantees no partial rows. Keeps single task-specified default without forking two sources of truth.
- **No new migration**: reuses `speech_segments`/`overlap_groups`/`segment_overlaps`/`artifacts`/`content_objects`/`artifact_parents`/`stage_output_artifacts`/`run_stage_summaries`/`stage_executions`/`provider_executions`; idempotency via delete-all-for-run + deterministic reinsert in one tx (safe: Diarization requires this barrier so no downstream segment units exist yet; same-attempt redelivery yields identical ids). Task's "unique (Run,Sequence)" handled in code, not a new DB constraint.
- **Overlap semantics**: cluster = transitive >100ms overlaps; group window = common intersection when non-empty else span of pairwise intersections; per-row window = segment∩group else widest pairwise for that member (always valid, else `PIPELINE_INVARIANT_VIOLATION`); relations `Contains` (covers, incl. equal) / `ContainedBy` / `Overlap`; order by start; micro-overlaps ≤100ms create no group (kept as adjacent timings, no relational rows). Equal-split for long speech documented (sub-threshold silence already merged away, so no silence midpoint remains; word edges within 200ms win when supplied).
- **Silence path**: zero VAD regions (or zero duration with zero regions) → zero segments, still publishes an (empty) `Segments` artifact, sets the four segment-stage summaries to 0, completes normally; the saga then skips downstream per-segment units. Positive regions with non-positive duration → `PIPELINE_INVARIANT_VIOLATION`.
