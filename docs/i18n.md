## The debt, and why it is a ratchet

`scripts/check-no-hardcoded-copy.mjs` is a ratchet, not a zero-tolerance gate,
and that was a decision rather than a shortcut.

Task 045's own Scope lists "feature screen copy" as **excluded** — that copy is
the deliverable of Tasks 019–036, six of which already shipped. Migrating 939
strings here would have rewritten 56 files and broken hundreds of assertions
owned by completed tasks, producing a diff nobody could review. So the gate does
the half that is actually possible on this task and keeps the other half visible:

- a **new** literal fails, in a new file or an existing one;
- an existing file's count may only go **down**;
- inflating the baseline is a visible two-place edit — the per-file map *and* the
  per-rule totals, cross-checked against each other and reported as
  `COPY_GATE_BASELINE_DRIFT` when they disagree.

`--strict` ignores the baseline entirely, which is how you see the whole picture
rather than the delta.

Regenerate with:

```bash
node scripts/check-no-hardcoded-copy.mjs --write-baseline
```

and say in the commit why the number went **up**. That is the review question.

## What the next task that touches a feature area should do

Extract that area's copy into `src/i18n/locales/en/<ns>.json` and read it with
`t()`. The gate will tell you the file and the line; `scripts/hardcoded-copy-baseline.json`
has the per-file and per-rule breakdown. A file that drops to zero disappears
from the baseline on the next regeneration — which is the point.

The enrichment panels (`features/enrichment/`) and the operator panels
(`features/admin/`) are the newest code in the tree and the most reasonable place
to start: nothing depends on their exact English, and Task 044's report
explicitly flagged them as the next extraction candidate.
