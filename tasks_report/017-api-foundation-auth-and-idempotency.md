## Decisions Made
- **HS256 SigningKey alongside OIDC Authority (no breaking change).** Task prescribes `Authority/Audience/RequireHttpsMetadata` only, which cannot issue test JWTs offline. Added optional `Auth:SigningKey` (HS256, `[Secret]`, 32+ chars); `ValidateIssuer=Authority?`, `ValidateIssuerSigningKey=true` always (both-empty fails closed with 401, mock/health/OpenAPI still boot). `RoleClaimType=roles` plus assertion accepting `roles/role/ClaimTypes.Role` for IdP interop. Tests set `Auth:SigningKey` via InMemory config.
- **Ownership enforced twice (handler + controller).** Handler does maintenance-scope load so cross-tenant yields 403 not 404 and never turns DB outage into 403 (catch→Succeed); controllers repeat the check explicitly (GET single loads maintenance-scope then compares, throwing `ForbiddenException`→403 envelope). Satisfies “route project.TenantId == claim tid else 403” with defense in depth.
- **401/403 envelopes, not empty statuses.** `JwtBearerEvents.OnChallenge/OnForbidden` + `IAuthorizationMiddlewareResultHandler` write the shared `ErrorResponse` shape with `CorrelationIdMiddleware.GetCorrelationId`, so `Unauthorized_401/Forbidden_Tenant_403` assert `error.code` + correlation header on auth failures too.
- **Idempotency via raw SQL ON CONFLICT (spec-literal) + EF fallback read.** `TryClaimAsync` uses `ExecuteSqlRawAsync` with `{0}` params (no concatenation) on `idempotency_records(tenant_id,endpoint,idempotency_key)` unique; conflict path loads via `Set<IdempotencyRecord>` in same `BeginScope`. `Complete/Fail/Reset` via `UPDATE ... WHERE tenant/endpoint/key`. Stored response is wrapper `{statusCode,body}` (inner body camelCase via `JsonSerializerDefaults.Web`); replay parses wrapper best-effort (fallback 200+raw). `Started<5min→IdempotencyInProgressException` (filter pre-sets `Retry-After`); stale/Failed/expired→reset to Started (treated as new claim).
- **Filter hashes bound args, not raw stream.** `IAsyncActionFilter` runs after model binding; reading the body stream would race binding. Hash = `ConfigurationHashCalculator.Compute(SortedDictionary(ActionArguments))` (canonical, secrets stripped) — different `targetLanguage` yields different hash → 409 mismatch. Missing/blank/overlong (>256) keys proceed-or-400 without claiming; non-mutations bypass.
- **Projects POST/GET/list real, others 501.** Task says shells return 501 yet tests demand `10 parallel POSTs→1 resource` + `403` + replay. Implemented minimal real Projects endpoints (create with audit, single with 403-vs-404 split, list with `PaginatedResult`) as 018 foundation; other 7 controllers stay 501 with correct policies. No business logic beyond what 017 tests need.
- **OpenAPI v2 API (interfaces, not classes).** `Microsoft.OpenApi 2.12` uses `IDictionary<string,IOpenApiSecurityScheme>`, `IList<IOpenApiParameter>`, `IDictionary<string,IOpenApiSchema>`, `document.Security` (not `SecurityRequirements`), `OpenApiSecuritySchemeReference(id,document)` + `OpenApiSecurityRequirement` dict, operation keys compared via `ToString()` (avoids missing `OperationType`). Null-guarded for `TreatWarningsAsErrors` (`if null→new` instead of `??=`).
- **Test JWTs via `System.IdentityModel.Tokens.Jwt` transitively.** No new package: `JwtSecurityTokenHandler` + `SymmetricSecurityKey(HS256)` with `tid/sub/roles[]`, audience `dubbing-api`, exp 1h. Factory marker stays `WebApplicationFactory<CorrelationIdMiddleware>` (avoids Api-vs-Workers `Program` CS0433). PG tests `SkippableFact` + Docker probe (MigrationTests pattern); 401/OpenAPI plain `Fact` (hermetic).
