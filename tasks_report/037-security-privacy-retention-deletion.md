## Decisions Made
- **Worker is plain `IConsumer`, not `BaseConsumer<DeletionJobRequested>` (task-text deviation)**: deletion jobs are project-scoped with an empty run id by contract; the base consumer would park every message (`Skipped` on empty run id, `Error` on missing run). Follows the 034 `ExportWorker` precedent; documented in worker docs.
- **`DeletionJobRequested` extends `IntegrationMessage` (not standalone)**: keeps the envelope/version/metric contracts uniform (contract test count bump 15→16 is the only fallout); project-scoping is carried by the empty `ProcessingRunId` plus `DeletionJobId`, documented on the contract.
- **Hold-blocked delete surfaces `POLICY_DENIED` → 403, not the task-text 409**: the frozen `ErrorCodes.StatusFor` catalog owns the mapping (`PolicyDenied→403`); the hold id is in the message as required. Same class of deviation as 034's `EXPORT_NOT_READY` mapping.
- **Refcount is derived, never stored**: artifact pins = live children referencing it + non-deleted artifacts sharing its bytes; content pins = any artifact row (per the 013 hook). No counter column exists to drift; `CanDeleteContentObjectAsync` is reused verbatim for the blob gate.
- **Content bytes use `FinalDays`**: a blob is shared across intermediate and final artifacts, so the conservative final window governs physical blob removal; per-type windows govern artifact-row removal.
- **`RequestDeletionAsync` completes the job synchronously; the worker/sweeper share `ExecutePendingAsync`**: no new API route was added (out of scope); `Pending` jobs arise from published `DeletionJobRequested` (future admin API) with the sweeper as backstop including stale-`Running` (>1h) takeover.
- **`RateLimiter` keys keep `ratelimit:`-first ordering**: renaming to literal `{tenant}:…` would break 036 dashboards/tests; keys remain tenant-scoped (tenant `N` always embedded, never shared), documented in `RedisKeys`, while new progress keys are literally tenant-first.
- **RLS interceptor/maintenance role unchanged (already correct)**: `TenantSessionInterceptor` active in both hosts, 44 policies in the initial migration, `BeginMaintenanceScope` for sweeper/reconciler paths; this task adds the `Maintenance__Connection` convention doc + append-only REVOKE (applied by operators in prod, not a migration, since it references the deploy-created `app_role`).
