## Decisions Made
- **Executed task number 023, not the literal filename**: `TARGET_TASK_FILE` named `023-context-build-worker.md` does not exist; per the sequential plan (`execution_tasks/README.md`: 023 = diarization, 025 = context-build) and completed 022, the correct next task is `execution_tasks/023-diarization-and-speaker-identity.md`, which was implemented. Context-build (025) was not started.
- **Queue follows task text + router**: task says queue `ai.provider` and `WorkQueueRouter.QueueFor(Diarization)` already returns `ai.provider`, so the worker documents `ai.provider` and `MassTransitConfig` was extended to attach extra consumers there (022 deferred this). All extra consumers now attach on both `media.preparation` and `ai.provider`; `ShouldProcess` pre-claim filters keep sharing safe.
- **SpeakerKey form**: normal keys `$"{projectId:N}:{label}"` (SHA-256 hex suffix when >128 chars); fallback key literal `"single"` per task. Speaker ids deterministic via `GuidUtility.From("speaker:"+key)` so reruns/redelivery are idempotent; legacy random-GUID rows are still reused by key (id kept).
- **DisplayName stability**: new labels get `Speaker {existingProjectCount + newPosition}` with new labels sorted ordinally; existing rows keep their names on reuse. Pure `Plan` (no DB) numbers `1..N` ordinally.
- **Missing-label segments keep their mapping**: provider labels that cover only part of the run leave uncovered segments untouched (no clearing), so partial mocks never wipe prior assignments.
- **Fallback records execution only when a request was built**: resolver/adapter failures before `DiarizationRequest` skip `ProviderExecution` (no call made); post-request permanent failures record with mapped `OutcomeClass` + fallback reason.
- **Transient-exhausted rethrows, permanent falls back**: in-process retry covers `HttpRequestException`/`TimeoutException`/`SocketException`/`IOException` + coded `RateLimited`/`Timeout`/`QuotaExhausted`/`Failed`; exhausted transients propagate to transport retry, permanent errors go to fallback/`PROVIDER_FAILED`. No in-service retry for permanent errors.
- **No new migration**: reuses `speakers` (unique `(tenant,project,speaker_key)`), `speech_segments`, `artifacts`/`content_objects`/`artifact_parents`/`stage_output_artifacts`, `stage_executions`, `provider_executions`, `quality_results`, `run_stage_summaries`.
