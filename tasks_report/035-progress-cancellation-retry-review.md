## Decisions Made
- **No new migration: manual versions use `Provider="manual"`** (task text says `IsManual=true`). `TranscriptVersion`/`TranslationVersion` have no manual column; adding one needs a migration for a display flag. Manual rows use `Provider="manual"`, `Model="manual-review-v1"`, confidence/scores `1.0`, reviewer linkage in `ReviewDecision.MetadataJson` (`manualVersionId/versionKind/segmentId`). Precedent: 026 keeps review state on `ReviewItem`, not version flags. Pure `IsManualVersion(provider)` centralizes the check.
- **`RetryService` returns a descriptor; controllers publish.** Application cannot reference MassTransit (no circular dep); the API host is publish-only (`MassTransitConfig` with `includeOrchestration:false`). `Publish(StageWorkRequested)` reaches workload-queue consumers by type subscription + `ShouldProcess` filtering — same mechanism as the existing `RunStarted` publish. Cost/rate enforcement stays dispatch-time in `WorkDispatcher` (Task 036-owned); retry enforces only the manual-attempt budget.
- **Selective retry resets summary counters for the retried stage + transitive dependents only** (task decision implemented as documented): `UPDATE run_stage_summaries SET *_units=0` preserving `ExpectedUnits`; `StageUnitCompletion` rows and artifacts untouched (immutable history); selected refs change only on new-attempt success (worker-owned). Segment-scope retries reset the whole stage counter (uniform rule; re-dispatch re-drives the retried unit, dependents re-run per barrier).
- **Reject never resumes (blocks).** `ResumesRun(Reject,*)=false`; controller publishes `ReviewResolved` without `StageType` so the saga (which unconditionally flips to `Running` on any `ReviewResolved`) performs no redispatch — the run cannot complete (barrier incomplete + RenderWorker open-review gate for still-open siblings) until requeue/retry. `RunStateMachine` intentionally untouched (`ManualReviewRequired→Failed` stays illegal; frozen machine + unit tests forbid extension).
- **`ProcessingController.Retry` and `SegmentsController.Retry` require Owner+** (task: cancel/retry Owner+). Processing retry previously allowed Editor — tightened to `RequireProjectOwner`. Review endpoints stay `RequireReviewer`.
- **SSE is poll-based (2s); Redis pub/sub deferred.** The Api host references no Redis client; the poll loop is the implemented transport (task allows "fallback poll 2s"). Event shape equals `GET progress` JSON (`data: {...}`), so a future `progress:{tenant}:{project}` subscriber can push without changing clients. Documented on the action.
- **Cancel accepts `Pending` (superset of the task's `Running/ManualReviewRequired`).** A `Pending` run holds barrier rows and blocks a second start; leaving it uncancellable would strand projects. `Cancelling` returns idempotently; terminal/905... terminal/missing → 404/409.
- **`ProgressResponse` shape replaced** (single construction site; no contract test pins the old `CompletedStages/TotalStages/PercentComplete` fields). Routes grow 32→33 (`progress/stream`); no 501s.
