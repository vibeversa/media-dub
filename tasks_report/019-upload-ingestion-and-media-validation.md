## Decisions Made
- **Worker is `IConsumer`, not `BaseConsumer` (required deviation).** Task text says `BaseConsumer<MediaUploaded>`, but `BaseConsumer.Consume` parks any message with `ProcessingRunId==Empty` or missing run in `_skipped`, and `UploadsController.PublishMediaUploadedAsync` publishes `ProcessingRunId=Guid.Empty` (no run exists pre-ingestion). Inheriting `BaseConsumer` would silently drop every ingestion. The worker instead mirrors `BaseConsumer`/`StageLeaseTimeoutConsumer` poison contracts (`MessageVersionPolicy`→`_skipped`, `DecideFailure`→`_skipped`/`_error`) and documents the reason on the class.
- **No new migration.** All ingestion rows reuse existing tables (`content_objects` unique `(tenant_id,content_hash)` as dedup authority, `media_assets`, `artifacts`+`metadata_json` jsonb, `stage_executions`, `upload_sessions.content_hash`, `dubbing_projects.status/source_media_asset_id/IsDeleted` shadow). `StageExecution`/`Artifact` use `uploadId` as `ProcessingRunId` per task (`run-or-norun` → `run=uploadId`); no FK constrains these to `processing_runs` (verified: configs define indexes only), so direct inserts are safe.
- **Copy, don't move, upload bytes.** Source bytes are re-uploaded content-addressed via `ArtifactService.PublishAsync` (which owns hashing/dedup/orphan-on-failure semantics + concurrent-unique-violation reuse); the original multipart object is left in place (reconciler-owned, never deleted by ingestion). FFprobe JSON goes through the same path (second `ContentObject` + `Artifact`) plus `UPDATE artifacts SET metadata_json` so both the "jsonb metadata" and bytes forms exist.
- **`MEDIA_UNSUPPORTED` vs `MEDIA_CORRUPT` split.** Probe execution/parse problems (exit≠0 incl. text-renamed-mp4, timeout after 1 retry, bad JSON) → `MEDIA_CORRUPT` (422, fail fast). Measurable policy violations (size/duration/container/codec, incl. mpeg4 video, missing audio) → `MEDIA_UNSUPPORTED` (415). `Invalid_Text_Renamed_Rejected` asserts exactly `MEDIA_CORRUPT` (verified live: ffprobe exits non-zero on text).
- **Project machine + re-upload latest-wins.** First ingestion follows `Created→Uploading→MediaReady/MediaRejected` with `EnsureCanTransition`; `MediaRejected→MediaReady` recovery and `Ready/Rejected→Ready/Rejected` re-uploads bypass the single-cycle machine via direct SQL (documented in `TransitionProjectAsync`); invalid never sets `source_media_asset_id`, valid always does (duplicate links existing asset id implicitly via returned `ExistingAssetId`).
- **Unit-test project gains `SkippableFact`.** Only IntegrationTests had the package; the live-ffprobe unit test needs `Skip` for ffmpeg-absent runners. Added same `1.3.12` version; fixed `Options.Create` → `global::Microsoft.Extensions.Options.Options.Create` (a `DubbingPlatform.UnitTests.Options` test namespace shadows `Options`).
